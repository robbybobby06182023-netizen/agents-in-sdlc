GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat では、こうした作業が手元のマシンでリアルタイムに行われます。各ツール呼び出しやファイル編集を確認し、差分をその場でレビューして、変更を個別に採用または却下できます。エディターを離れずに追加のプロンプトを送り、作業を調整・拡張することもできます。

この演習では、アクセシビリティエージェントの作業をリアルタイムで監視し、提案されたファイル編集をレビューして採用し、進行中のセッションに指示を出してハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティのカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマを暗すぎると感じる利用者向けに、ライトモードも切り替えられるようにします。新しい会話を始める代わりに、進行中のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作を含めてチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドなどが表示されます。
3. ファイル編集が提案されたら、差分を確認します。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャットの上部にある **Files changed** を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に変更内容の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けることで、エージェントは先ほどの作業（変更したコンポーネント、スタイルの方法、設定を保持する local storage のパターンなど）のコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に次のプロンプトを送ります。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストのときと同じように、新しい編集を確認して **Keep** または **Undo** を選択します。
4. エージェントが意図と異なる方法（たとえば、好ましくない形で切り替え UI をリファクタリングするなど）に進んだ場合は、チャット入力欄の隣にある **Stop** で停止し、追加の説明を送ります。

> [!TIP]
> 実行中のセッションに追加の指示を出すほうが、最初からやり直すより効率的です。「セレクターの重複ではなく CSS 変数を使って CSS を簡潔にする」「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する」「両方の切り替えにキーボードショートカットを追加する」などのプロンプトで、方針を修正したり範囲を広げたりできます。

## 作業対象をレビューする

コミットする前に、エージェントが変更したファイルを簡単に確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれているはずです。
3. いくつかのファイルを開いて差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、カスタムエージェントが指示したアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode を使い、進行中のセッションを監視して指示を出しました。ファイル編集をレビューして採用または却下し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または却下する。
- 進行中のセッションに追加のプロンプトを送り、エージェントに指示を出す。

次は[アクセシビリティの作業を PR として公開][next-lesson]し、ラボ全体でローカルのカスタムエージェントが行った変更をレビューします。
